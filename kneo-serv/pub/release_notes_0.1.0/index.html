    Kneo Agent Platform 0.1.0 release notes¶

    Date: 2026-05-07

    Summary¶

    Kneo Agent Platform 0.1.0 is the first public release of the kneo-serv Python package — a standalone service layer on top of the Kneo Agent SDK. The service keeps platform concerns (FastAPI routing, auth, durable state, audit, redaction, policy persistence, CLI workflows) in kneo_serv, while agent, runtime, workflow, human-in-the-loop, skill, tool, and middleware integration is delegated to the SDK's high-level surfaces by default.

    SDK alignment¶

    • Depends on kneo-agent>=1.1.1,<2.0.0; the release dry run installed kneo-agent 1.2.0.
    • Runtime, workflow, skill, tool registry, middleware, and telemetry adapters route through SDK definitions where the service does not need persistence, redaction, or policy-specific hooks.
    • Local wrappers that remain are documented as service boundary code in docs/sdk_alignment.md.

    Service APIs and CLI¶

    • Public APIs are available on both legacy unversioned routes and /v1.
    • Run, spec, human-task, audit, credential inventory, and environment-policy routes use structured response models and structured error payloads.
    • Credential inventory endpoints return redacted secret-reference status only.
    • Environment policy endpoints persist policy state in project metadata and support read/update operations for deployment overlays.

    Security and audit¶

    • API keys can be assigned explicit scopes or roles: admin, operator, reviewer, service, and viewer.
    • Credential inventory requires credentials:read; policy reads require policies:read; policy writes require policies:write.
    • Audit events are persisted for run/spec/human/credential/policy surfaces and are redacted before storage and again before listing.
    • docs/production_readiness_review.md records the route scope matrix, role boundaries, audit payload review, and intentional privilege tradeoffs.

    Operational assumptions¶

    • PostgreSQL integration tests remain opt-in with KNEO_SERV_RUN_POSTGRES_INTEGRATION=true and KNEO_SERV_DATABASE_URL.
    • deploy/production.env is local-only and ignored; source artifacts include deploy/production.env.example, not real deployment secrets.
    • Real provider integration remains opt-in and requires provider credentials.
    • Health and readiness endpoints are public for infrastructure probes; readiness output must remain limited to status and redacted secret presence.
    • OpenTelemetry is wired through the SDK telemetry middleware and should keep argument/result capture disabled unless the deployment has approved the data classification.
