    kneo-agent 1.2.0¶

    A backwards-compatible minor release focused on production reliability, on-prem deployment, and enterprise data-source integration through the SDK's existing tools and MCP surface. Every public name from 1.1.x still works the same way.

    pip install --upgrade kneo-agent is safe — read docs/upgrading_to_1.2.md for a code-level walkthrough of what's new.

    Highlights¶

    🏠 Run on local LLMs¶

    First-class base_url= / api_key= on every OpenAI entry point. Point at Ollama, vLLM, llama.cpp, or LocalAI in one call:

    from kneo_agent import build_sync_agent

agent = build_sync_agent(
    "openai",
    base_url="http://localhost:11434/v1",
    model="llama3.1",
    system_prompt="You are a concise assistant.",
)

    🛡️ Production middleware bundle¶

    New kneo_agent.middleware subpackage — drop-in, stdlib-only:

    • RetryMiddleware — exponential backoff + jitter
    • RateLimitMiddleware — token-bucket throttle
    • TokenBudgetMiddleware — per-run / cumulative caps from RunResult.metadata["usage"]
    • RedactionMiddleware — regex scrubbing with a COMMON_PATTERNS starter pack

    Pairs cleanly with OpenTelemetryMiddleware; recommended ordering documented in the package and in docs/agent_middleware_guide.md.

    🔐 Secrets without leaks¶

    New SecretProvider Protocol + EnvSecretProvider / FileSecretProvider / MappingSecretProvider. The runtime_checkable Protocol means you can plug in your own Vault / AWS Secrets Manager / GCP Secret Manager implementation with a single class.

    from kneo_agent.utils import EnvSecretProvider, FileSecretProvider

# K8s/Docker secret-mount pattern
secrets = FileSecretProvider("/var/run/secrets/myapp")
api_token = secrets.get("api_token")

    A regression test suite asserts representative secret shapes (Bearer tokens, JWT, AWS keys, OpenAI keys, embedded-credential URLs) never reach logs, OTel spans, exception messages, or tool-result strings when RedactionMiddleware is in the chain.

    🔒 MCP behind corporate TLS¶

    MCPServerConfig.http() and .sse() now accept verify=, ca_bundle=, client_cert=, client_key= so on-prem agents can reach internal MCP servers without monkey-patching urllib.

    config = MCPServerConfig.http(
    name="internal",
    url="https://mcp.internal.corp/v1",
    ca_bundle="/etc/ssl/corp/ca.pem",
    client_cert="/etc/ssl/corp/client.crt",
    client_key="/etc/ssl/corp/client.key",
)

    🔁 Workflow retry¶

    kneo_agent.workflows.RetryStep wraps any WorkflowComponent (Agent, FunctionStep, nested Workflow) with retry-on-failure. Preserves the inner component's name so existing WorkflowBuilder.add_edge(...) references keep matching.

    📊 Standardized usage metadata¶

    RunResult.metadata["usage"] now has a documented shape: {"input_tokens", "output_tokens", "total_tokens"} (with prompt_tokens / completion_tokens accepted as aliases). The OpenAI Agents native runtime populates it automatically; OpenTelemetryMiddleware reads the documented keys to emit GenAI semantic-convention attributes.

    LangChain / Google ADK / Bridge runtimes don't yet populate the field — apps that need usage on those paths can populate via custom middleware. Per-runtime rollout is tracked for a follow-up release.

    New cookbook recipes¶

    Seven runnable patterns under examples/cookbook/. All run offline in CI; each documents the swap to a real client inline.

    Recipe What it shows
    local_ollama.py base_url= against a local OpenAI-compatible server
    workflow_branching_and_retry.py WorkflowBuilder.add_edge(condition=...) + RetryStep
    mcp_server_catalog.py YAML/JSON catalog of MCPServerConfig entries
    sql_query_tool.py Read-only parameter-bound SQL over SQLite (psycopg2/pymysql/pyodbc swap)
    rest_api_tool.py Per-host REST tool with auth via SecretProvider
    object_store_tool.py MinIO / on-prem S3 list/get/put via endpoint_url=
    search_index_tool.py Elasticsearch / OpenSearch query tool with allow-list

    New docs¶

    • docs/api_stability.md — public-surface definition; three stability tiers; deprecation policy.
    • docs/upgrading_to_1.2.md — practical "should I upgrade?" walkthrough.
    • docs/self_hosted_observability.md — wiring OpenTelemetryMiddleware to OTLP collector / Jaeger / Grafana Tempo / SigNoz.
    • docs/offline_install.md — air-gapped install via pip download + --no-index --find-links. The SDK does not phone home (audit-grade); the guide spells out exactly which outbound calls the SDK can make and why.

    The API Reference Manual (docs/kneo_agent_api_reference.{html,pdf}) has been regenerated with a v1.2.0 banner and a "What's new" callout.

    Quality¶

    • 261 tests pass, 10 skipped (external resources / soft doc checks).
    • Coverage 86.12% (gate: ≥85%).
    • mypy --strict clean across 49 source files.
    • New import-no-extras CI job asserts that the four optional extras (agents, langchain, google.adk, opentelemetry) are not pulled into the core install.
    • New tests/unit/test_public_api_snapshot.py pins the 75 top-level __all__ names — accidental drift fails CI.
    • New tests/integration/test_doc_example_drift.py — every examples/...py path mentioned in any doc must exist and be either smoke-tested or explicitly skipped with a reason.

    Compatibility¶

    • Python 3.12+. CI exercises both 3.12 and 3.13; 3.13 classifier added to pyproject.toml.
    • No removed names. No renamed parameters. No narrowed return types. See docs/api_stability.md for the formal policy.
    • All public surface is pinned by tests/unit/test_public_api_snapshot.py.

    Project metadata¶

    • Added CODE_OF_CONDUCT.md (Contributor Covenant 2.1, by reference).
    • Added SECURITY.md. Vulnerabilities go through GitHub's private security advisories — see the doc for details.
